# Internationalisation

The dashboard is translatable and direction-aware. English is the source
language; every other language is a catalogue that overrides it.

## Writing strings

```tsx
import { useTranslation, Trans } from 'react-i18next';

const { t } = useTranslation();
<button>{t('Add monitor')}</button>
<p>{t('{{count}} events selected', { count })}</p>
<Trans>Switch in <Link to="/settings">Settings → Appearance</Link>.</Trans>
```

- **The key is the English text.** No invented ids. `t('Add monitor')` is the
  whole convention; `en/translation.json` maps it to itself.
- Interpolate, never concatenate: `t('Showing {{from}}–{{to}} of {{total}}', …)`.
  Word order changes across languages.
- Plurals: write the singular, `t('{{count}} monitor', { count })`. Extraction
  emits `_one`/`_other` and `scripts/i18n-plurals.mjs` fills the English
  plural from its noun dictionary (add the noun there when it reports one it
  does not know). The `en` catalogue is bundled so plurals work everywhere,
  tests included.
- Outside React (stores, API error mapping) use `i18next.t()` from `@/i18n`.
- Aria labels, titles, placeholders and `document.title` are strings too.
- Do not translate: log messages, API field names, enum wire values, monitor
  names, anything a user typed.

## Extraction

```
npm run i18n:extract   # rewrites every catalogue in src/locales/
npm run i18n:check     # CI: fails if any catalogue is out of date
```

`i18next-parser` scans `src/**` for `t()` / `<Trans>` and rewrites **all**
catalogues, not just `en`: the English one maps each key to its own text, the
others gain new keys as empty strings and lose keys the code no longer uses.
Existing translations are preserved — the parser merges. The locale list is
read from `src/locales/`, so adding a directory is all it takes to include a
language.

This used to run for `en` alone, and the other catalogues drifted 720 keys
behind the UI before anyone noticed. `i18n:check` now diffs the whole
directory for the same reason.

## What ZoneMinder can and cannot give us

ZoneMinder's catalogue is **757 strings**; this UI has **1,739**, and only
**208 (12%)** overlap. The PHP interface never had to write empty states,
explanatory hints or filter-builder vocabulary, so no importer can do better
than about an eighth of the UI — the seeder prints that ceiling on every run
so the coverage table is not read as a target.

Everything else needs real translators. Untranslated values are empty
strings, and i18next falls back to the key, which is the English text: a gap
reads as English, never as `events.list.title`.

## Seeding from ZoneMinder

ZoneMinder ships 27 translations in `web/lang/*.php`. When a dashboard string
matches one of ZM's English strings — ignoring case, surrounding space and a
trailing `:`/`…`/`?` — the seeder copies ZM's translation:

```
node scripts/i18n-from-zm.mjs --zm ../ZoneMinder         # all languages in src/i18n/languages.ts
node scripts/i18n-from-zm.mjs --zm ../ZoneMinder --langs de,he --dry
```

Only exact matches are used and existing translations are never
overwritten. Expect 20–40% seeded coverage; the rest is for translators.

## Direction (RTL) and writing modes

- `applyDirection()` (`src/i18n/direction.ts`) sets `<html dir lang>` from the
  active language. Hebrew is RTL today; Arabic and Persian are reserved.
- **Layout uses logical CSS only**: `ms-`/`me-` not `ml-`/`mr-`, `ps-`/`pe-`,
  `start-`/`end-`, `text-start`/`text-end`, `rounded-s-`, `border-s`. Tailwind
  v4 maps these to CSS logical properties, so the whole layout mirrors with
  no per-component code. `scripts/codemod-logical-css.mjs` rewrites physical
  utilities; run it on new code if you slip.
- Directional icons (chevrons, arrows, back/forward) get `rtl:-scale-x-100`.
  Play/pause, clocks, checkmarks do not flip.
- **Physical media never mirrors.** Video stages, the montage wall,
  timelines/scrubbers, the PTZ pad, zone polygons and charts sit in a
  container with `dir="ltr"`: left in the picture stays left.
- Numbers: use `Intl.NumberFormat`/`toLocaleString` with the active locale;
  keep tabular data `tabular-nums`. Dates go through the shared formatter
  (`src/lib/format.ts`) which takes locale and the ZoneMinder date format.
- **Vertical writing modes** (`writing-mode: vertical-rl`, e.g. traditional
  Mongolian or tategaki Japanese) are not a target for UI chrome — no
  ZoneMinder locale uses one, and no surveillance UI does. Logical
  properties mean block/inline axes would still resolve correctly if a
  future locale set `writing-mode` on `<html>`; physical media stays
  horizontal regardless.

## Adding a language

1. Add it to `LANGUAGES` in `src/i18n/languages.ts` (code, native name,
   `dir`, and the ZM file if one exists).
2. `npm run i18n:extract`, then seed: `node scripts/i18n-from-zm.mjs --langs <code>`.
3. The language appears in Settings → Appearance once
   `src/locales/<code>/translation.json` exists. Catalogues load lazily.

## Testing

Tests run with English keys and no catalogue, so `t('Monitors')` renders
`Monitors` and existing text assertions keep working. For direction, assert
`document.documentElement.dir` after `changeLanguage('he')`.
